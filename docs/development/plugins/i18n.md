# Internationalization (i18n) for plugins

Headlamp plugins can include translations. Use the `headlamp-plugin` CLI to set up i18n, extract translatable strings, and add locales.

Minimal steps:

- Add an npm script to run the extractor (if missing):

  ```json
  "scripts": {
      "i18n": "headlamp-plugin i18n"
  }
  ```

- Install the required tool dependencies by running:

  ```bash
  npm run frontend:install
  npm run app:install
  ```

- Then you can start adding new translations by running the i18n script
  with a language code. For example:

  ```bash
  npm run i18n -- es
  ```

- The command above will:

  1. Create a new i18n section to the package.json of the plugin:

    ```json
    "headlamp": {
        "i18n": ["es"]
    }
    ```

  2. Create the translation file for that locale in `locales/es/translation.json`. This is the file you will need to translate.

- To update the locales after a string addition or change, run `npm run i18n`.

## Adding a language with a plugin

A plugin can add a language that Headlamp does not include, with Headlamp's
own strings in it, by calling `registerLocale`:

```ts
import { registerLocale } from '@kinvolk/headlamp-plugin/lib';
import { fiFI } from '@mui/material/locale';
import { MRT_Localization_FI } from 'material-react-table/locales/fi';
import app from '../locales/fi/app.json';
import glossary from '../locales/fi/glossary.json';
import translation from '../locales/fi/translation.json';

registerLocale({
  code: 'fi',
  label: 'Suomi',
  resources: { translation, glossary, app },
  muiLocale: fiFI,
  tableLocalization: MRT_Localization_FI,
});
```

- `resources` holds Headlamp's catalogs in the language, by namespace, with the
  keys of the English catalogs in `frontend/src/i18n/locales/en/`. A key the
  plugin's catalog lacks shows the English string. Importing the JSON files
  bundles them into the plugin, so a translation reaches users with a new build
  of the plugin. Add `"resolveJsonModule": true` to the plugin's
  `tsconfig.json` for the imports to type-check.
- `muiLocale` and `tableLocalization` are optional. They give Material UI's
  components and the tables their strings in the language.
- `label` is the language's name in the language itself. It appears in the
  locale selector under Settings.

Headlamp switches to the language when the user asked for it ahead of every
language Headlamp already has: by opening Headlamp with `?lng=<code>`, by
choosing it on an earlier visit, or by listing it first in the browser's
language settings.

## Changing Headlamp's strings in a language

`registerLocale` also changes Headlamp's strings in a language Headlamp
includes, English among them. List only the keys to change:

```ts
registerLocale({
  code: 'en',
  resources: { glossary: { Namespaces: 'Projects' } },
});
```

- The plugin's strings replace Headlamp's for the keys it lists. Every other key
  keeps Headlamp's string, so translations that a later Headlamp release adds or
  corrects still reach users.
- A change to English also shows in every language whose catalog lacks the key,
  because those languages fall back to English.
- `muiLocale` and `tableLocalization` replace Material UI's and the tables'
  strings in the language. `label` and `dir` apply only to a language Headlamp
  does not include.
- The code is matched without regard to case, so `zh-tw` changes `zh-TW`.

When more than one plugin registers the same language, including one a plugin
added, their strings are merged, and the plugin loaded last wins for each key.

Other plugins translate their own strings into the language as they do for any
language, with `headlamp.i18n` in their `package.json` and
`locales/<code>/translation.json`.

The desktop app's menus come from the Electron process, which does not load
plugins, so they stay in English.
