# Internationalization (i18n) for plugins

Headlamp plugins can include translations. Use the `headlamp-plugin` CLI to set up i18n, extract translatable strings, and add locales.

Minimal steps:

- Add an npm script to run the extractor (if missing):

  ```json
  "scripts": {
      "i18n": "headlamp-plugin i18n"
  }
  ```

- Install the required tool dependencies by running:

  ```bash
  npm run frontend:install
  npm run app:install
  ```

- Then you can start adding new translations by running the i18n script
  with a language code. For example:

  ```bash
  npm run i18n -- es
  ```

- The command above will:

  1. Create a new i18n section to the package.json of the plugin:

    ```json
    "headlamp": {
        "i18n": ["es"]
    }
    ```

  2. Create the translation file for that locale in `locales/es/translation.json`. This is the file you will need to translate.

- To update the locales after a string addition or change, run `npm run i18n`.

- Read strings through the hook the plugin library exports. The build injects
  the plugin's name, so the hook loads the plugin's own catalogs:

  ```tsx
  import { useTranslation } from '@kinvolk/headlamp-plugin/lib';

  function PodCounter() {
    const { t, ready } = useTranslation();
    if (!ready) {
      return null;
    }
    return <span>{t('Loading…')}</span>;
  }
  ```

  The [pod-counter example](https://github.com/kubernetes-sigs/headlamp/tree/main/plugins/examples/pod-counter)
  uses it, with English and Norwegian Bokmål catalogs.

## Adding a language with a plugin

A plugin can add a language to Headlamp itself, with Headlamp's own strings in
it, by calling `registerLocale`:

```ts
import { registerLocale } from '@kinvolk/headlamp-plugin/lib';
import app from '../locales/nb/app.json';
import glossary from '../locales/nb/glossary.json';
import translation from '../locales/nb/translation.json';

registerLocale({
  code: 'nb',
  label: 'Norsk bokmål',
  resources: { translation, glossary, app },
});
```

`resources` holds Headlamp's catalogs in the language, by namespace, with the
keys of the English catalogs in `frontend/src/i18n/locales/en/`. `muiLocale`
and `tableLocalization` take Material UI's and the tables' strings for the
language. The language appears in the locale selector, and Headlamp switches
to it when the user asked for it ahead of every language Headlamp already
has: with `?lng=<code>`, by choosing it on an earlier visit, or in the
browser's language list. A language Headlamp already includes cannot be
replaced.

Other plugins translate their own strings into the language as usual, through
`headlamp.i18n` and `locales/<code>/translation.json`. The desktop app's menus
come from the Electron process, which does not load plugins, so they stay in
English.

The language-nb example in `plugins/examples/language-nb` adds Norwegian
Bokmål this way. On Headlamp releases without `registerLocale`
it falls back to finding Headlamp's i18next instance in the React tree; its
README lists what that covers.

## Translating a plugin with kapi

[kapi](https://neokapi.github.io/kapi/) can keep a plugin's catalogs in step
with its English source. In the Headlamp repository, each plugin that has
catalogs gets a collection in the root `kapi.yaml`:

```yaml
collections:
  - name: plugin-pod-counter
    base: plugins/examples/pod-counter
    content:
      - path: "locales/en/translation.json"
        format: i18next
        target: "locales/{lang}/translation.json"
```

A plugin in its own repository gets a `kapi.yaml` of its own:

```bash
kapi init --source-locale en --target-locale nb
```

Point its collection at `locales/en/translation.json` with the `i18next`
format, as above. Then the loop is the same as for Headlamp itself: run
`npm run i18n` to extract new strings, and translate them with `kapi up`, a
coding agent writing through `kapi apply`, or a translator working on the
XLIFF files `kapi extract` writes. See
[Translating with kapi](../i18n/contributing.md#translating-with-kapi).
Headlamp's `.kapi/terms.json` holds the Kubernetes terminology the UI uses.
Copy it into the plugin's own `.kapi/` and run `kapi store import`, so the
plugin's translations follow the same words.
