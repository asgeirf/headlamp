# Internationalization (i18n) for plugins

Headlamp plugins can include translations. Use the `headlamp-plugin` CLI to set up i18n, extract translatable strings, and add locales.

Minimal steps:

- Add an npm script to run the extractor (if missing):

  ```json
  "scripts": {
      "i18n": "headlamp-plugin i18n"
  }
  ```

- Install the required tool dependencies by running:

  ```bash
  npm run frontend:install
  npm run app:install
  ```

- Then you can start adding new translations by running the i18n script
  with a language code. For example:

  ```bash
  npm run i18n -- es
  ```

- The command above will:

  1. Create a new i18n section to the package.json of the plugin:

    ```json
    "headlamp": {
        "i18n": ["es"]
    }
    ```

  2. Create the translation file for that locale in `locales/es/translation.json`. This is the file you will need to translate.

- To update the locales after a string addition or change, run `npm run i18n`.

## Adding a language with a plugin

A plugin can add a language that Headlamp does not include by calling
`registerLocale` with Headlamp's strings in that language:

```ts
import { registerLocale } from '@kinvolk/headlamp-plugin/lib';
import { fiFI } from '@mui/material/locale';
import { MRT_Localization_FI } from 'material-react-table/locales/fi';
import app from '../locales/fi/app.json';
import glossary from '../locales/fi/glossary.json';
import translation from '../locales/fi/translation.json';

registerLocale({
  code: 'fi',
  label: 'Suomi',
  resources: { translation, glossary, app },
  muiLocale: fiFI,
  tableLocalization: MRT_Localization_FI,
});
```

- `resources` contains Headlamp's catalogs in the language, by namespace,
  with the keys of the English catalogs in `frontend/src/i18n/locales/en/`.
  Missing keys are shown in English. The imported JSON files are bundled into
  the plugin, so updated translations require a new build of the plugin. To
  type-check the imports, add `"resolveJsonModule": true` to the plugin's
  `tsconfig.json`.
- `muiLocale` and `tableLocalization` are optional. They provide the
  Material UI and table strings in the language.
- `label` is the name of the language, written in that language. It is shown
  in the locale selector in Settings.

Headlamp switches to the new language if the user requested it before all
languages that Headlamp includes: by opening Headlamp with `?lng=<code>`, by
selecting it on an earlier visit, or by listing it first in the browser's
language settings.

## Changing Headlamp's strings in a language

You can also use `registerLocale` to change Headlamp's strings in a language
that Headlamp includes, including English. List only the keys to change:

```ts
registerLocale({
  code: 'en',
  resources: { glossary: { Namespaces: 'Projects' } },
});
```

- The plugin's strings replace Headlamp's strings for the listed keys. The
  other keys keep Headlamp's strings, so translations that later Headlamp
  releases add or fix are still used.
- A change to English is also shown in every language whose catalog does not
  contain the key, because these languages fall back to English.
- `muiLocale` and `tableLocalization` replace the Material UI and table
  strings in the language. `label` and `dir` are used only for a language
  that Headlamp does not include.
- The language code is not case-sensitive, so `zh-tw` changes `zh-TW`.

If more than one plugin registers the same language, including a language
that a plugin added, their strings are merged. For each key, the string from
the plugin loaded last is used.

Other plugins translate their own strings into the language in the usual
way, with `headlamp.i18n` in their `package.json` and
`locales/<code>/translation.json`.

In the desktop app, the Electron process creates the menus. It does not load
plugins, so the menus are shown in English.
